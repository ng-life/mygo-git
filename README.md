# MyGo Git

基于 MyGo v0.8.3 的原生 Go Git 桌面客户端，管理多个本地 Git 仓库。

## 启动

要求 Go 1.27.3+、Git，以及 MyGo 所需的平台图形环境。

```sh
go run .
```

构建：

```sh
CGO_ENABLED=0 go build -o bin/mygo-git .
./bin/mygo-git
```

## 下载与 GitHub Actions

源码：<https://github.com/ng-life/mygo-git>。每次 push 到 main、提交 Pull Request 或手动触发 Build，Actions 都会执行测试、race 和 MyGo UI 检查，再构建 macOS ARM64 / Intel、Windows AMD64、Linux AMD64 产物。构建完成后在 Actions 的 Artifacts 下载，各平台附带 SHA-256 校验文件。

macOS 下载包包含 `.app`，目前采用 ad-hoc 签名，未做 Apple 公证。Windows 提供独立 exe；Linux 提供归档和 Debian 包。运行时仍需系统 Git；语法跨文件跳转需安装 ripgrep。

推送 `v*` Tag 后，Actions 会在构建通过后创建 GitHub Release 并上传产物。发布前同步修改 `mygo.json` 中的版本。

## 本地开发与人工验证

功能完成、检查通过后执行：

```sh
./scripts/dev-restart.sh
```

脚本先构建临时二进制，成功后只停止当前 checkout 的旧客户端，再替换并启动新版。Git / SSH 子进程未结束时最多等待 60 秒，不强杀正在执行的 Git 操作。启动 PID 与日志分别位于 `bin/dev.pid`、`bin/dev.log`，不会修改用户的仓库、Changelist 或扫描配置。

## 使用

1. 点击顶部「设置」，添加一个或多个扫描文件夹，既可以直接添加 Git 项目，也可以添加父文件夹，支持系统目录选择器多选。点击「保存并扫描」后立即扫描，启动时也会扫描已保存目录。所选文件夹为第 0 层，最多向下扫描 3 层；发现仓库后停止深入该目录。支持普通仓库和 `.git` 为文件的 worktree；相同仓库路径自动去重。扫描目录保存在配置目录的 `settings.json`；移除扫描目录不会移除已添加仓库。
2. 左侧通过 `Repositories`、`Changes`、`Logs` 三个逆时针旋转 90° 的纵向 TAB 切换。`Changes` 独立展示工作区变更与提交；`Logs` 统一展示 `HEAD (Current Branch)`、`Local`、`Remote`、`Tags`。分支和 Tag 名按 `/` 拆分层级并跨仓库分组，远程分支保留远程名；忽略远程 HEAD 符号引用。末级节点不显示展开按钮。
3. 节点数字表示拥有该分支（或该前缀下分支）的仓库数。同一仓库在同一前缀下只计一次。
4. 点击分支加载对应仓库的合并 Log。右键真实分支执行 checkout、merge、rebase、Fetch、Pull 等批量操作。
5. 支持刷新状态、Fetch、Pull 和切换分支。Pull 操作每个仓库的**当前分支**，使用 `--ff-only`。切换分支与 Pull 遇到未提交修改会跳过。
6. 下方 Log 展示所选仓库当前分支或所选分支的提交。选中提交后，Log 内显示变更文件子视图；选中文件后，上方文件区展示变更前后内容。未选提交时隐藏 Log 的文件列表；`Repositories` 和 `Logs` 未选文件时上方留白，`Changes` 的工作区变更位于左侧栏。工具栏「操作结果」可展开 Git 命令的执行结果。

清单保存在系统用户配置目录的 `mygo-git/repositories.json`；macOS 下通常为 `~/Library/Application Support/mygo-git/repositories.json`。保存的是仓库路径与可选名称，不保存凭证。名称默认取 origin 命名空间，无 origin 时取目录名；名称不参与分支分组。

## 提交与文件浏览

1. 选择仓库，查看该仓库当前 HEAD 的 Log；选择本地或远程分支，查看对应引用的 Log。选择分支目录时，合并该目录下的分支历史。
2. 多仓库提交按提交时间倒序合并展示，每行保留来源仓库、完整 SHA 的悬停信息和作者。同一个 SHA 在不同仓库中保留各自的行。已移除分支对应的仓库摘要区，仓库范围由左侧选择决定。
3. 点击 Log 行选择单条提交；按住 Control（macOS 也支持 Command）点击可增减选择，Shift 点击可连续选择。变更文件按仓库和文件路径去重汇总，不同仓库中的同名文件保持独立。取消全部选择后隐藏文件子视图。
4. 点击文件，上方文件区通过 Inline 或 Side-by-side 展示变更前后的 UTF-8 文本，标记修改行并显示行号。多个所选提交修改同一文件时，按提交分段连续展示，保留仓库和 SHA，不包含未选提交的变更。每段与该提交的第一父提交比较，初始提交与空树比较；支持新增、删除、重命名和普通修改。二进制、非 UTF-8 文件和子模块显示说明。
5. 每仓库最多读取 200 条提交。每侧文本最多加载 1 MiB，超出时显示限制说明。diff 使用虚拟列表，仅构建可见行附近的控件，支持长文件全行浏览和横向滚动，不再截断为 5000 行。Log 中的历史比较为只读，不包含工作区未提交修改；工作区比较入口位于 `Changes` 左侧栏。

左栏与文件区之间的分隔线可左右拖动调整宽度，各 TAB 在本次运行中分别保留宽度，双击恢复默认值。Changes 工作区的仓库名始终单行显示，超出时以 `…` 省略；悬停可查看完整名称与路径。

所有树（Repositories、Changes、Logs 和 Review）统一使用「单击箭头展开／收起，双击节点内容展开／收起」。单击内容保留仓库、引用或文件选择行为；勾选框单独控制提交范围，双击内容不联动勾选。没有子节点的末级不显示展开箭头，双击也不会创建展开状态。

文件区与 Log 之间的分隔线可拖动调整；双击恢复默认比例。切换仓库、分支、提交或文件会清理下级选择；同一范围刷新保留仍存在的提交和文件选择。过期读取会取消，过期响应也不会覆盖当前内容。

## 快捷键与后台任务

macOS 使用 Command，其他平台使用 Ctrl。顶部「快捷键」可查看完整列表；打开确认或设置对话框时，不执行窗口级提交、拉取等快捷键。

| ⌘R | 刷新当前视图；Compare 刷新当前比较范围 |
| ⌘⇧R | 刷新全部仓库 |

右下角显示运行中的任务名称、当前仓库／阶段、步骤进度和任务数量；点击「任务」查看详情。多仓库 Pull、Fetch、分支操作、Commit、Push、Tag 和状态检查按实际步骤更新，进度不是耗时估算。总量尚未确定的读取和扫描使用活动进度条。失败信息保留仓库／阶段来源，部分失败不会显示为全部成功；过期读取取消后不会覆盖新任务。详情在本次运行中保留最近 20 个已结束任务，并保留全部正在运行的任务。

## Logs 引用选择与右键操作

HEAD 与 Local、Remote、Tags 使用相同树行，文字对齐；HEAD 没有展开箭头。单击选择引用，Ctrl / Command 点击增减选择，Shift 按当前可见树的顺序连续选择。折叠层级和搜索隐藏的引用不进入 Shift 范围。右键已选引用保留多选，右键未选引用改为单选该项。

- **单选** HEAD、本地分支、远程分支或 Tag：可直接与 HEAD、Worktree 比较，或打开「与指定版本比较…」填写分支、Tag、SHA。直接比较使用两个端点的最终差异，不默认改为共同祖先比较；Worktree 包含未提交及未跟踪文件。
- **双选**：显示正向和反向比较，按选择顺序确定基准与目标。仅比较同时包含两个引用的仓库，菜单显示共同仓库数量；没有共同仓库时禁用比较。
- **三选及以上**：不展示比较、checkout、merge、rebase 等单目标操作，只保留刷新、Fetch 和删除等批量入口。Fetch 对去重后的仓库各执行一次。
- **批量删除**：确认对话框列出引用和影响仓库；本地分支使用安全删除，远程分支沿用并发更新保护与远端回读核对，Tag 仅删除本地引用。HEAD 不可删除；单项失败不阻止其他项执行，结果逐引用、逐仓库显示。
- **单选新建与重命名**：支持从任意所选引用创建本地分支，不自动切换工作分支；本地分支可重命名，已有名称不覆盖。原有 checkout、merge、rebase、Fetch、Pull 和 Tag 菜单继续保留。

多选 Log 汇总各仓库所选引用的历史；本地、远程与 Tag 使用完整引用名，避免同名分支或 Tag 混淆。

## IDEA 风格界面

界面采用固定 Darcula 深色主题：工具窗口使用 `#3c3f41`，代码区使用 `#2b2b2b`，蓝色选中行、紧凑树与表格、低圆角按钮贯穿 Repositories、Changes 和 Logs。原生窗口外观同步为深色。

Log 展示时间、作者、真实提交拓扑、仓库、提交说明和 SHA，支持按说明、SHA、作者或仓库搜索。提交图按仓库与 SHA 区分节点，展示真实父子关系；父提交不在当前加载、筛选或显示顺序范围内时以端点标记，不补画推测连线。图布局按输入缓存，表格继续仅构建可见行。筛选后的 Shift 连选仅包含当前可见提交。

选择提交后，Log 右侧展示按仓库和紧凑目录分组的变更文件树，点击文件在上方打开比较；文件树下方展示提交摘要。Log 与文件树之间的分隔栏可拖动，双击恢复默认比例。Diff 的 Inline、Side-by-side、语法高亮、复制选择及 Ctrl 跳转沿用现有交互，增删内容使用深色背景。

## Changes 工作区与 Commit

`Changes` 上区采用多 Changelist 管理，按 Changelist、仓库和文件夹层级列出 HEAD 与工作目录的最终差异及未跟踪文件，本地分支移至 `Logs` 的 `Local` 分组。没有变更的仓库不显示在变更列表中；提交成功且工作区变干净后自动移除对应仓库分组，Changelist 保留。每组显示实际工作分支；左侧选中的历史分支只影响下方 Log，Commit 始终面向该仓库当前工作分支。

1. 进入 `Changes` 自动加载变更，或点击「刷新变更」。外部修改文件后可手动刷新。
2. 勾选需要提交的文件；仓库和各级文件夹支持展开、折叠及勾选，单一路径中的中间文件夹会合并为 `src/main/java` 这样的紧凑节点；存在多个子节点或直接变更文件时保留分层。父级勾选会联动所有可提交的子文件，部分选中时显示半选状态。仓库、目录和文件采用紧凑树结构，展开箭头、勾选框及文件图标分列对齐；仓库行显示名称、变更文件数和当前分支，目录旁显示子树的变更文件数。单击箭头或双击目录内容可展开或折叠，也可用顶部「折叠」「展开」操作整棵变更树。树下按新增、修改、删除和冲突汇总数量，提交说明使用独立的 Commit Message 区域。新增及未跟踪文件显示绿色，修改及重命名显示浅蓝色，删除显示灰色；文件名和文件图标使用相同状态颜色，原始 Git 状态通过悬停查看，冲突以橙色提示。冲突文件不能勾选，仍需先解决冲突再提交。点击文件，在右侧比较 HEAD 与当前工作区的完整内容，包含已暂存和未暂存修改。
3. 在共享的「Commit message」输入框填写提交说明，支持多行。所有本次选择的仓库使用同一份原始 message。
4. 点击仓库行内的「Commit」，仅提交该 Changelist 下该仓库中已勾选的文件。点击「Commit」，依次提交所有有勾选文件的仓库。
5. 提交后只重新检查本次涉及的仓库和工作区；Log 按引用解析出的 SHA 缓存，未变化的历史直接复用。各仓库组和「操作结果」展示核对结果及成功提交的 SHA。

勾选文件按工作区完整内容暂存并提交，不提供按变更块或部分暂存内容提交。未勾选但已暂存的文件保留在暂存区，不会被本次 Commit 顺带提交。支持首次提交、新增、修改、删除和重命名；重命名旧路径出现额外工作区变更时，需刷新并确认文件选择。

Commit 命令返回后会独立核对 HEAD、所在分支、父提交、message、变更范围和文件内容。命令异常但核对一致时记为成功；命令失败且确认未产生提交时记为失败；读取失败、并发修改或核对不一致时显示「结果待确认」，保留 message，不自动重试。请核对仓库历史后再操作；hook 改写 message 或文件内容也可能进入待确认状态。

批量 Commit 是各仓库独立执行的提交，不是跨仓库事务。某个仓库失败后继续处理后续仓库，已成功的提交不会自动回滚。失败仓库保留文件选择、message 和当前暂存状态；Git hooks 和签名配置照常生效。工作区存在冲突或未完成的 Git 操作时拒绝提交；分支或 HEAD 与读取时不一致时要求刷新。刷新发现分支或 HEAD 已变化会清除该仓库的文件选择。

成功仓库清除已提交文件的选择。单独提交后仍有其他已选仓库时保留 message；全部已选仓库成功提交后清空 message，任一仓库失败时保留 message 以便重试。

Changes 左侧栏分为上下两区：上区展示未提交工作区和提交操作，下区按仓库展示未 Push 提交。分隔线可拖动调整，双击恢复默认 60% / 40%。本地、远程分支及 Tags 统一在 Logs 中浏览。右上文件区完整用于文件比较。选择 Log 提交或历史文件会退出当前工作区文件比较，并继续使用历史浏览功能。

## Changelist 管理

- 默认有 `Default` 列表，点击标题旁的「+」新建列表，可同时设为活动列表。活动列表接收刷新时首次发现的变更，原有变更保持原分组；同一文件的后续修改继续属于原列表。
- 单击列表内容选择列表并勾选其文件，同时切换该列表的 Commit Message 草稿；单击箭头或双击内容展开、折叠。每个列表的仓库及目录展开状态独立。
- 右键列表可设为活动列表、重命名、删除或 Revert 整个列表。默认列表不可删除；删除其他列表仅将其变更移回默认列表，不修改文件和 Git 暂存区。
- 文件、目录和仓库行右键可移动到已有列表，或移至新建列表；也可勾选多个仓库的文件后使用「移动所选…」批量移动。当前按完整文件分组，同一文件不能拆成多个列表。
- 一个列表可跨多个仓库；顶部总提交按钮按实际勾选文件跨列表、跨仓库提交，使用当前编辑的同一份 message。仓库行内 Commit 只处理该列表内的文件。
- 列表名称、活动列表、当前编辑列表、独立 message 草稿和文件归属保存到配置目录的 `changelists.json`。归属按仓库路径与本地分支隔离；刷新后移除已提交或撤销文件的归属。切换分支保留其他分支的归属。
- 所有操作都是客户端分组管理，刷新与移动均不会执行 Add 或清理暂存区。配置读取失败时显示提示并停止覆盖原配置。

## Changes 上下分区与发布操作

上区采用 Changelist 模式，展示 HEAD 与工作目录的最终差异及未跟踪文件，按 Changelist、仓库与紧凑目录分组。仅暂存区存在差异、工作目录已恢复为 HEAD 的文件不展示（例如暂存新增后又删除的 `AD` 文件）；冲突文件仍保留。此展示不会清理或修改暂存区，Repositories 的未提交颜色标记使用相同口径。文件、目录和仓库的勾选决定提交范围：

- **Commit**：单仓库行内按钮或「Commit」执行现有文件级提交，保留未勾选的暂存内容。
- **Commit & Push**：共享 message，先逐仓库提交并核对成功，再推送该仓库当前分支；对话框允许分别设置 remote 和目标分支。推送范围包含该分支先前所有未 Push 提交。Commit 成功但 Push 失败时保留本地提交，清除已提交文件的选择，后续仅需在下区重试 Push。
- **Amend**：勾选 message 旁的 Amend 后，将所选文件补入最新未发布提交并更新 message，不混入其他暂存文件。单仓库且 message 为空时尝试填入原 message。无文件修改时，可右键下区最新提交选择「Amend 最新提交…」仅修改 message。当前 HEAD 已被任何本地远程跟踪引用包含时拒绝 Amend。
- **Revert**：文件右键「Revert 此文件…」或勾选单个／多个文件后点击「Revert…」。确认列表会说明影响范围：已跟踪文件恢复到 HEAD，同时丢弃所选暂存及未暂存内容；尚未提交的新增文件会从暂存区和磁盘删除。未选择文件及其暂存内容保留。重命名恢复旧路径并清理新路径；文件已变化、冲突、目录／子模块或未完成 Git 操作会拒绝执行。此操作不能恢复未提交内容，需核对确认列表。

下区按仓库列出当前分支的完整未 Push 提交集合，使用独立的虚拟列表，不受 Log 每仓库 200 条的限制。单击提交查看变更，勾选用于合并历史：

- **Push**：仓库行内「Push…」或「Push 全部…」可设置 remote 与目标分支，按固定 HEAD 推送，不使用强制推送。推送后核对实际 push 地址上的分支 SHA。首次按同名分支推送时保存 upstream；远程拒绝或无法核对时展示失败／待确认，保留本地提交。
- **合并所选提交**：至少选择同仓库两个未发布提交，并填写合并 message。只支持线性历史，遇到 merge commit 或已经发布的提交会拒绝处理。不连续选择会先按原顺序合并所选提交，再按原顺序重放其间和后续未选提交；重放冲突时停止。

合并在临时索引中应用补丁并创建候选提交，保留作者与后续提交 message，执行 `commit-msg` hook，并按 `commit.gpgsign` 配置签名。只有最终文件树与原 HEAD 完全相同、工作区仍干净、HEAD 和分支仍一致时，才使用原 SHA 做比较并更新分支；失败时不自动修改原分支、主暂存区或工作区。原 HEAD 保留在分支 reflog 中。需要干净工作区，不自动 stash；hooks 自身的副作用不会自动撤销。

未 Push 与已发布判断均基于本机远程跟踪引用，外部推送后应先 Fetch 再刷新。文件 Revert、Push 和历史合并均通过操作对话框核对范围，各仓库独立执行，不自动回滚其他仓库。

## Compare：比较代码与 ref 提交集合

从 Logs 引用右键比较或 Review 进入 Compare。顶部 A、B 可填写分支、完整 ref、Tag、Commit SHA、HEAD 或 Worktree，点击「比较」应用；「交换」会交换方向，支持 Worktree → ref 的反向差异。比较范围沿用入口选定的仓库。

- **文件差异**：区分 A → B 的最终文件差异与共同祖先 → B 引入的改动；支持路径／仓库搜索、状态筛选、未读过滤及原有跨文件导航。
- **仅 A／仅 B／双方独有**：按 Git 可达关系展示 SHA 独有的提交，汇总多个仓库，并标记 Git 判断为补丁等价的提交。等价标记不代表 SHA 相同；没有标记也不作为业务语义不同的证明。
- **共同祖先**：显示各仓库的 A、B 完整 SHA 和全部 merge base；可选某个祖先作为该仓库的比较基准。多个 merge base 时，不自动选取其中一个。
- 单击提交查看文件，Ctrl／Command 增减选择，Shift 连选。多选提交的文件视图保留每条提交相对第一父提交的变化；切回文件差异查看两个端点的净差异。
- 每侧、每仓库先加载 200 条提交，显示完整集合计数，提供「加载更多提交」。文件差异不受此提交条数限制。分页沿用首次比较解析出的 SHA；显式重新比较才重新解析可移动引用。
- 提交集与文件 Diff 共用各仓库一次解析的版本快照。切换范围时取消旧读取并拒绝过期结果；只在选择提交后加载该批提交的文件比较。
- **忽略空白**使用 Git `-w` 重新计算文本变更块，保留原始文件内容。替换行增加行内词段高亮；无修改内容仍可展开查看。
- 默认每侧文本上限 1 MiB；明确勾选「加载大文件」后，本次 Compare 上限提高到 8 MiB，继续使用虚拟 Diff。二进制、非 UTF-8 与超过上限文件保留说明。
- Worktree 不属于提交历史，涉及 Worktree 时禁用独有提交和共同祖先视图；文件比较包含未跟踪内容。

## 快捷 Review

工作区和历史文件默认使用变更块视图，显示旧、新行号与增删标记，并保留前后各 3 行上下文。相邻上下文重叠时合并为一个变更块；其余未修改内容折叠，可点击「展开 N 行未修改内容」查看。通过「Inline」「Side-by-side」切换布局：Inline 在同一列交错展示删除与新增行；Side-by-side 左旧右新，对齐对应变更行并同步纵向滚动，两侧可分别横向滚动。切换文件时保留布局选择。点击「完整文件」展开全部上下文，再点击「变更块」恢复折叠；上下文显示范围与布局独立。两种布局都保留虚拟列表和横向滚动。

代码文本支持鼠标跨行拖选、复制和右键复制菜单，复制内容不包含行号或增删标记。普通拖动用于选字，Ctrl+点击标识符跳转定义。

- 「上一文件」「下一文件」按文件列表顺序连续浏览；工作区支持跨仓库导航，历史范围来自当前所选提交的文件汇总。也可使用 `Shift+F8` / `F8`；二进制或读取失败的文件仍可继续导航。
- 「上一变更块」「下一变更块」跳转当前比较中的变更块；焦点位于比较区时可使用 `Shift+F7` / `F7`。多条所选提交仍按提交分别展示各自的比较及变更块导航。
- 根据文件名自动识别语法，复用 MyGo 内置分词器，支持 Go、Java、C#、JavaScript、TypeScript、Python 等语言。关键字、字符串、数字和注释使用不同颜色，多行注释保留跨行状态；未识别的文件按纯文本显示。完整文件与变更块视图均支持高亮。

## 统一 Review

工具栏的「Review…」统一审查工作区、分支或 Log 中选中的提交。仓库右键菜单的「Review… · 当前工作区」仅作用于该仓库；分支右键菜单的「Review… · 图形比较此分支」作用于拥有该分支的全部仓库。工具栏入口使用当前仓库或分支范围，没有选择时使用全部仓库。

比较基准支持分支名、远程跟踪引用和 Commit SHA：

- **基准 → 工作区**：比较基准版本与当前工作区的最终内容，包含已暂存、未暂存和未忽略的新文件。默认基准为 `HEAD`；首次提交前以空树比较。
- **共同祖先 → 目标**：分别解析基准和目标，以唯一共同祖先比较目标版本，适合审查功能分支引入的改动。存在多个共同祖先时提示改用直接比较。
- **基准 → 目标**：直接比较两个版本的最终内容，包含两端各自开发造成的差异。
- **所选提交**：使用 Log 中 Control/Command/Shift 选中的提交；支持跨仓库。

范围内各仓库分别解析引用，界面显示引用名称、完整 SHA，以及共同祖先模式实际使用的祖先 SHA。失败仓库单独报告，其余仓库继续展示。比较在后台读取，取消或重新选择范围后，过期结果不会覆盖当前界面；引用移动和外部文件修改后，通过「刷新 Review」重新读取；「刷新全部」及仓库操作完成后也会刷新当前 Review。文件区展示本次读取的快照。

进入 Review 后，下方显示按仓库和紧凑目录分组的变更树，点击文件在上方查看图形 diff；沿用 Inline / Side-by-side、语法跳转、变更块导航及 `F8` / `Shift+F8` 连续文件导航。「结束 Review」返回 Log；切换左侧 TAB、仓库或分支也会结束当前 Review。

分支及提交 Review 支持「净差异」「逐提交」切换：

- **净差异**展示最终结果，重复修改会合并，已完全撤回的修改不再出现。所选提交按 Git 祖先关系确定端点，从最早所选提交的第一父提交比较到最晚所选提交，**包含端点之间未选中的提交**；所选提交不在同一祖先链时提示使用逐提交模式。
- **逐提交**保留每条提交相对其第一父提交的改动。所选提交模式仅展示所选提交；分支模式展示目标可达且基准不可达的提交，每仓库最多最近 200 条，超出会明确提示。净差异没有这项提交条数限制。工作区始终展示净差异。

通过文件行的「未读／已读」或文件区的「标记已读／标记未读」保存审查状态。「只看未读」过滤文件树及连续导航；过滤时标记当前文件已读会自动打开下一待审查文件。进度按仓库范围、比较基准、目标及比较模式分别保存在配置目录的 `review-progress.json`，重启后再次打开同一范围即可恢复。刷新检测到文本、二进制内容、权限或重命名变化时，对应已读标记失效；读取失败的文件不能标记已读。切换净差异与逐提交模式各自保留进度。

## Ctrl+点击语法跳转

在变更块、完整文件或定义预览中，按住 `Ctrl` 点击标识符可查找定义。普通点击不会触发跳转，注释和字符串中的普通文本不参与跳转。

1. 先使用当前文件已准备的分析结果，查找作用域内的声明、局部变量或已知接收者类型的方法；能找到时不会调用 ripgrep。
2. 文件内找不到时，使用当前文件的语言、导入信息和接收者类型筛选仓库内的候选文件，再用 ripgrep (`rg`) 搜索符号。只对匹配文件进行声明分析，过滤注释、调用位置以及不匹配的声明种类或参数数量。
3. 一个目标直接打开只读定义预览，并滚动到目标行；多个目标列出名称、所属类型、路径和行号，选择后打开，可返回目标列表。预览中支持继续 Ctrl+点击；关闭预览后保留原来的 diff 和选择。

Go 使用标准库 AST 处理文件内词法绑定、变量遮蔽、参数和声明；跨文件支持同目录包和当前仓库 `go.mod` 所声明模块内的导入路径。Java、C#、JS/TS、Python、C/C++ 使用轻量声明分析，结合作用域、接收者类型和参数数量筛选；JS/TS 支持相对导入及具名导入别名。它不使用 LSP 或编译器完整类型检查，不保证解析继承、动态分派、泛型推导、复杂重导出、宏及外部依赖；无法确认时提示未找到，或保留多个候选供选择。

历史比较始终在对应侧的 Git revision 中搜索和读取定义，不使用当前工作区代替。历史跨文件搜索会临时提取最多 250 个相关文本文件，完成或取消后清理；最多分析 60 个匹配文件，达到限制时显示结果可能不完整。文本文件上限仍为 1 MiB，ripgrep 搜索超时为 10 秒。跨文件跳转需要 `rg` 可执行文件在 PATH 中；缺失时界面提示，文件内跳转仍可使用。

## 单仓库操作

`Repositories` 顶部提供仓库搜索，可按名称或路径筛选，不区分大小写；已移除「全部仓库」按钮。单击仓库内容选择该仓库的 Log；单击箭头或双击内容展开、折叠当前工作区文件树。箭头不改变 Log 范围。每个仓库在名称后紧跟当前分支，采用紧凑单行展示，长名称省略，悬停查看完整路径、分支和状态。仓库名保持普通文字颜色，分支名以浅蓝色表示存在未 Push 提交，以橙色表示存在未提交变更；两者同时存在时使用橙色，并保留浅蓝色的 `↑ N` 未 Push 数量。数量优先相对推送引用、其次相对上游引用计算；没有可用引用时统计尚未被任何远程跟踪引用包含的提交。不主动访问远端，Fetch 后再刷新可更新本地判断。

文件树按需读取 Git 已跟踪文件及未忽略的新文件，不列出已删除文件；单一路径中的中间目录合并为紧凑节点。单击箭头或双击目录内容展开、折叠，单击文件在右上查看当前工作区内容，包括没有变更的文件。文件视图支持上一/下一文件、语法高亮、选择复制和 Ctrl+点击跳转。执行「刷新全部」或相关仓库操作后，已展开的文件树与当前文件会重新读取。

`Logs` 顶部统一搜索本地分支、远程分支和 Tag，按完整名称筛选并保留祖先层级。引用叶子显示所属仓库，悬停可查看完整仓库清单；Local、Remote、Tags 分组可独立折叠。仓库搜索与 Logs 搜索分别保留，筛选不改变当前 Log 范围及批量操作目标。点击 HEAD 恢复各仓库当前分支历史。

右键仓库可刷新状态、Fetch、Pull、查看工作区 diff 和当前分支 log。通过「本地分支操作」「远程分支操作」子菜单选择分支，再执行 checkout、merge、rebase、diff、log 或删除分支。所有仓库右键操作仅作用于所右键的仓库，不受其他仓库选择状态影响。工作区 diff 比较 HEAD 与当前工作区，包含已暂存和未暂存的已跟踪文件修改，不包含未跟踪文件。

## 分支右键菜单

右键真实分支节点可执行以下操作，纯层级目录不提供 Git 操作。菜单顶部明确显示目标分支及影响的仓库数。

| 操作 | 含义 |
| --- | --- |
| checkout | 将各仓库切换到该分支 |
| merge | 将该分支合并到各仓库当前分支，自动接受默认合并提交说明 |
| rebase | 将各仓库当前分支变基到该分支 |
| diff | 比较各仓库当前 HEAD 与该分支的提交内容，显示文本补丁；不含工作区未提交修改 |
| log | 查看该分支最近 30 条提交 |
| 删除本地分支 | 使用 `git branch -d` 安全删除，不提供强制删除 |
| 删除远程分支 | 删除所选远程跟踪引用对应服务器上的分支，并核对结果；本地分支保留 |

在 `Logs` 的 `Local`、`Remote` 分组中右键分支时，操作作用于**拥有该完整分支名的全部仓库**，不受当前 Log 提交选择影响。各仓库独立执行，某个仓库失败不影响后续仓库，结果按仓库分别显示。

删除操作先在应用内确认分支名及影响仓库。同名分支批量删除时，各仓库独立执行，失败后继续处理后续仓库，并自动刷新分支树与 Log。本地当前分支、其他 worktree 正在使用的分支、未合并分支及存在未完成 Git 操作的仓库会跳过。远程删除使用本地跟踪引用的 SHA 作为显式 lease；远程分支已有新提交时拒绝删除，需 Fetch 后重新检查。删除针对所选远程的 fetch 地址，避免配置了不同 pushurl 时误删其他 fork。服务器保护规则及 hooks 照常生效；无法核对远程结果时标记「结果待确认」，不自动重试。

远程 checkout 会创建并跟踪对应远程分支，例如 `origin/feature/order` 对应本地 `feature/order`；已有本地分支仅在跟踪关系相同时复用，否则跳过，不覆盖已有分支。

checkout、merge、rebase 遇到未提交修改或未完成的合并、变基、拣选操作时跳过。发生冲突时保留 Git 操作状态，在结果区提示手动处理或执行 `git merge --abort` / `git rebase --abort`。不自动丢弃变更或回滚其他仓库。

## Tags 管理

`Logs` 中的 `Tags` 展示本机已有 Tag，按名称层级合并，同名 Tag 的各仓库对象可以不同，操作会分别处理。点击 Tag 或目录可查看对应历史，Tag 与同名分支始终使用独立引用。右键 Tag 可进入图形 Review、查看历史、切换、推送、创建或删除；「新建 Tag…」按钮使用当前引用涉及的仓库，也可在对话框中逐个勾选。

- 新建支持轻量 Tag、附注 Tag、任意分支或 Commit SHA 目标，不覆盖已有 Tag。
- checkout 会进入 detached HEAD；有未提交变更或未完成 Git 操作时跳过。
- 删除仅影响本地 Tag，先确认仓库清单，并使用读取时的对象 ID 核对和原子删除；引用已变化时拒绝删除。远程 Tag 保留。
- 推送需要指定已配置的 remote 名称，默认 `origin`；推送读取时的精确对象，不强制覆盖不同的远程 Tag。
- 「获取 Tags」对各仓库执行 `git fetch --all --tags`，不强制覆盖冲突 Tag。远程存在但尚未获取的 Tag 需先获取才会显示。

批量操作独立执行，部分失败不回滚已成功仓库；结果按仓库展示，完成后刷新引用与 Log。

## 当前边界

- 远程分支来自本机保存的远程跟踪引用；需执行 Fetch 才能更新远程状态。
- 批量 Git 操作串行执行，每条命令超时 90 秒。Log、提交文件和文件内容在后台按需读取；切换选择时取消过期读取并丢弃过期结果。macOS/Linux 等 Unix 平台取消命令时同时结束该命令进程组内的 hooks/SSH 子进程。文件原始内容读取超时为 30 秒。认证使用本机已有凭证或 SSH agent，禁用交互式凭证输入。
- 工作区保护以执行前的 Git 状态检查为准；不执行 stash、reset、强制切换或自动解决冲突。
- 当前版本不包含克隆和差异编辑功能；文件比较区只读。右键分支 diff 在操作结果区显示文本补丁；图形比较使用「Review…」。
- 仓库扫描最多深入 3 层，发现仓库后停止深入；跳过子目录 `.git`、`node_modules`、`vendor`，不跟随子目录符号链接。显式添加的符号链接目录会解析到实际目录，不可访问目录会报告。
